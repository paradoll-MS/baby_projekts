2. 技术建模（建议以`函数/模型`定义任务）
>变量
>- `P(properties)` = `P1` + `P2`  ----配方的嗅觉和客观属性
>- `F(formula)` ----配方本身
>- `I(ingredient)` ----原料  `t`(threshold)
>- `GC`
>- `node` ----（P1和P2的具体节点）
>
`P1`的`node`是不同层级的嗅觉语言（从韵/味到协调等，内部也有网络）；`P2`的`node`是理化/价格/法规等。按照惯例，`node`有属性和值，可以理解为神经元，它们之间也可以有层级。

>函数/模型
>- `I(initiate)` ----从未知GC到初始F_0
>- `T0` ----针对`P2`的理化计算/预测函数
>- `J(judge)` ----对P2的硬约束判断
>- `T` ----基于当前配方和P的优化需求
>- `T1`(advanced) ----从P1直接到F_guess（适用于更高级的功能）
>- `N`(NLP+) ----处理非结构化自然语言和客户画像，预测P_goal

>理想方程建模
>- I(GC_对标) = F_0 或者 I(GC_对标，P) = F_0
>- T0(F) = P2 , J(P2) = 0/1
>- T(F_now,ΔP) = F_update
>- N(B) = P_goal , M(P_goal) =  F_likely
>- T1(P) = F_guess
>
`T`函数关心的是基于现有配方`F_now`和改动需求`ΔP`（比如"减甜"，“提高闪点”）给出possible的`F_update`；`价格`已有。

3. 细致分析`函数/模型`
    - `I` 的起点是人工修正完成的GC报告（仍需求证：如果合理设定软件参数是否可以减少修正工作量？），期待比目前的极少天然油参考提供更多求解。我认为我至少需要知道调香师到底到底有没有做“因为GC未识别的单体在某个天然油里而加上”或“因为闻到味道加上的原料确实符合那些常见单体（比如蒎烯）”这样的动作。如果有，那么这个起点的优化是有意义的。
    - `T0`&`J`拆解：`闪点`和`溶解性`强相关可以用预测模型（预估数据应该足够）；`稳定性`需要专业知识（接专家包），`法规`如果没有现成工具可以自建；
    - `N`这个的关键是统计+人工辅助先形成`P1`的`node`，然后就是NLP。另外我们把连接客户画像和通用需求的训练也融入在这里。
    - `T`为关键功能。这是最好玩的复杂模型训练任务，多层节点。我们的训练依据：数据驱动线（预估数据量是不够的）是配方和描述，物理约束线是共识经验量化和改动经验的学习，可能是trans，复杂，好好研究。`thrshold`在这个模型训练里起到的作用类似于电子鼻减去基线的操作，对于本就不足的数据量来说一定是重要的。
    - `T1`应该不在这一层级的功能要求中。而且肯定得等`T`实现了才能到这，因为node的绝对量化（相当于给描述赋值）一定是难于相对量化的。
