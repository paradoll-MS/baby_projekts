## niche & evaluation
1. 前置工作：
    -  **结构化已有数据**【基本功能的基础】：（量化/tagging，不要求一开始就减少噪声）
        - 一个`产品`——配方/嗅觉描述/历史客单匹配/销存情况
        - 一个`原料`——GC/嗅觉描述/理化性质（HSP）/采购分析（进存&稳定＆成本）
        - 一次`客单`——【创】brief迭代和配方迭代的时序信息 【推】需求/成产品 【败】
        - 市场`报告`——prevalence/画像接受度
    
    - **制作感官数据**【进阶的基础】：
        - `描述单元`：tag（可以借鉴POM或者观察内部惯用词典） + 强度（相对数值，需要先研究和找可用的OAV数据）
        - 了解到更好地贴近嗅觉体验可能需要OAV经过物化沙箱模拟的动态数据
        - 预估这个需要对香本身有更多经验

2. 针对不需要调香只需要推荐的情况
    - 目前已知确有需求：在给客户推荐产品的时候销售会忘掉以前的产品和以前的案例；
    - 做一个内置小智能体：根据`产品`，历史`客单`，同时如果我们完成了`报告`部分的结构化，就可以智能辅助针对当前客户的产品推荐。
    - input处理好，训练智能体。

3.  市场部分析helper系列
    1. 纯码非ai类
        - 基于久谦跨境商品数据的详情爬取和信息统计程序
            - 200个商品一个个点进去看香型+对着表格手动算一遍的重labour劳动
            - 这个任务要做的话需要确认具体需求
            - 集成到中控上或者并行使用server
    2. ai类（参考Takasago Ai-T-Aroma的工作，可以尽力模仿）
        - 潜力：舆情爬取，分析增强，预测模型
        - 理论可做，打磨需要时间
        - wy姐评价这个会比较有价值

4. GC优化？
- 这个图谱解析目前用的是哪一代分析方法？是否还有优化的空间？
- 如果有微量高效物质的难检出情况普遍，可以考虑硬件（如生物传感）但这个很科研先只是写在这里。

5. 合规部门的及时抓取信息和update到中控上问题
    - 调香师反馈更新滞后
    - 合规人员搜检与匹配进度可以大幅优化

6. 辅助调香系统（main）
    - 体系分析：
        - 系统目标：符合需求/嗅觉描述，符合香气协调性经验，原料稳定，成本约束，合规具有否决性
        - 奖励函数建模：对每个成本和违规约束，模型以GC的猜油求解为起点，加权优先符合需求/嗅觉描述、符合经验、具备稳定性的搭配

    - 阶段目标：
        - （先完善数据体系后）第一步是看模型的起点是哪里，也就是基于GC中比较显式的部分，是否可以直接方程遍历一些base，作为训练的起点（当然也可以先直接当作一个智能计算器用上）
   
    - 潜力：（参考Symirise的achievement）从模型本身反解隐性特征关联；可以随时纳入新的约束条件（比如有一天也开始走环保路线...）

    - 需要进一步了解：合规问题？基质的HSP？天然基质？
    - reference
        - 总结自Gary：70%的一般客户其实主要诉求是产品的客群接受度和一点流行趋势；小部分的高端客户则需要在反复对接和引导下确定一款香；或者兼有但侧重其一。
        -  目前了解到的任务类型案例：
        
        
        | 客户input                | 销售output   | 调香师input(＋常规)  |
        |------------------------|---------|---------|
        | 模仿市售/不明物香味  | /   | GC+嗅觉   |
        | “爆款玫瑰香气+喷雾+120+高端” 或者“类似XXX这种香水但是稍微XXX一点”  | “清透瓜香+玫瑰+水基+120+不能太甜” （例子为青瓜玫瑰）  | 描述   |
        | 希望这个已有香再XXX一点   |同  | 原配方+描述   |
        | / | / | 一种基于原料的构思（需要协调） |
        - 常规 = 报价+原料情况+基质/HSP+相应法规+else
